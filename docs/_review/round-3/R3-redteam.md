# R3 — Independent Red-Team Review (delivered code)

**Project:** Saman ERP (`F:\harness\saman-erp`) · **Round:** 3 (design **and** implementation) · **Date:** 2026-10-20
**Scope:** the *code that exists*, not the catalogue: `apps/api/src/**`, `packages/db/**`, `packages/shared/**`, `.env.example`, `docker-compose*.yml`, `infra/**`.
**Inputs:** `docs/04-security/SECURITY.md`, `THREAT-MODEL.md`, `docs/03-api-contract/API.md` §2/§5/§6/§7, `docs/_review/round-1/R1-security.md`, `R1-accounting.md`, `docs/adr/0004–0014`.
**Method:** every SECURITY claim was treated as untrusted and traced to code/SQL. Findings below only include things I could pin to a line of delivered code and describe an exploit for. Where the code *is* sound it is listed under *Verified fixed from R1*.

**Severity:** **Blocker** = deploy/install impossible, or a control the docs call mandatory is absent while the release notes call it implemented; **High** = privilege, money, PII or availability impact with a realistic pre-condition; **Medium** = needs a pre-condition/insider or has bounded impact; **Low** = hardening/spec drift.

## Verified fixed from R1 (implementation-level)

1. **B-02 device-trust forgery — genuinely fixed in code.** Trust requires the server-issued 256-bit `saman_device` cookie whose HMAC matches `user_devices.device_secret_hash`; the client-supplied fingerprint is only a display label. A password login with a copied fingerprint and no/!matching cookie returns the 202 OTP challenge (`auth.service.ts:669-695`, `auth.repository.ts:397-441`, cookie issuance `auth.service.ts:616-635`). *(Still unreachable in practice because of B-01/B-06.)*
2. **B-03 public reset endpoints — absent.** There is no `/auth/password/forgot` or `/auth/password/reset`, and no users controller; the public endpoints R1 flagged cannot be called. The admin-assisted flow is not implemented either, so this is "no weaker path exists", not "the stronger path works".
3. **B-06 core registry/key-matching — partially fixed.** One generated registry (`permissions.generated.ts`, 415 keys), exact string matching in `hasPermission` (`permissions.ts:276-299`), and **every** permission key used on a delivered route exists in the registry (171 used / 0 unknown; checked programmatically). The bidirectional CI parity and `reserved` marking are still missing (M-07).
4. **H-03 webhook signature configuration — fixed.** Header names, algorithm and mandatory-ness are compile-time per adapter; `channel_account.settings` overrides are rejected by a forbidden-key regex (`webhook-signature.ts:43-72`, `channel-accounts.service.ts:36-58`).
5. **M-03 webhook replay — fixed.** The MAC covers `channel.account.eventId.timestamp.rawBody`, the timestamp is mandatory with ±300 s skew, and the archive dedupes on `(channel_account_id, external_event_id)` and reports a payload-hash mismatch for a reused event id (`webhook-signature.ts:75-90,142-205`, `channel-webhook.repository.ts:123-152`).
6. **M-05 / H-04 SSRF and outbound exfiltration — fixed at the service layer.** Adapter hosts are code-declared with HTTPS-only, no IP literals/userinfo, port 443 (`egress.ts:30-63`); outbound webhooks use a fixed allowlist, re-resolve DNS and reject private/link-local answers, forbid redirects, and strip cost/secret fields unconditionally (`egress.ts:63`, `outbound-webhook.service.ts:51-67,202-222`).
7. **H-12 DB grants — partially fixed.** `saman_app` loses `DELETE`/`TRUNCATE` and `UPDATE`/`DELETE` on `audit_logs`, `inventory_transactions`, `channel_api_calls`, `api_request_logs`; `saman_readonly` is revoked from the identity/secret tables (`0001_init.sql:5718-5726`). Still incomplete: worker can delete everything (H-01), default privileges re-grant DELETE (M-10), readonly still reads business PII (H-10).
8. **M-01 OTP purpose / security-event vocabulary — fixed structurally.** `otp_challenges.purpose` and `security_events.event_type` are now free `varchar` columns (no restrictive CHECK), so the events/purposes the controls require can be stored (`0001_init.sql:312,375`). Purpose binding on consumption is *not* enforced (B-06/M-02).
9. **M-02 idempotency-key actor scoping — fixed.** The unique key is now `(organization_id, actor_user_id, scope, key)` (`0001_init.sql:653`).
10. **H-11 secrets-by-file — implemented for the API/worker crown secrets.** `*_FILE` indirection is real (`env.schema.ts:248-278`) and Compose mounts `jwt_access_secret`, `app_encryption_key`, `otp_pepper`, `refresh_pepper`, `db_password`, `redis_password` as files (`docker-compose.yml:56-62,213-218`). Still defeated by `.env` env_file, MinIO/Grafana env values and shared DB passwords (H-02/H-03).

Report this as verified, not as a weakness.
12. **R1 L-02 edge ports — fixed.** The web container listens on 8080 and only Caddy publishes 80/443; the web process runs as uid 101 with `cap_drop: ALL` (`docker-compose.yml:287-312,373-398`).

## Verdict

**Not releasable — the delivered tree cannot be installed or logged into, and the controls the delivery claims are either unwired or contradicted by the SQL.**

The two most serious classes are (1) **wiring failures that make all security controls inert**: the authentication guard is never registered (B-01), the audit interceptor is never registered (B-05), step-up has no guard (B-07), scope has no guard (B-09), and OTP delivery is not wired (H-06); and (2) **integrity failures in the database**: the migration cannot apply (B-02), journal posting targets a non-existent column (B-03), the seeded admin hash cannot be verified by the API (B-04), the audit chain hashes no auditable content and the worker can delete it (H-01), and all DB roles share one password (H-02).

The R1-C blockers are not all closed: **B-04 is still open** (approval thresholds remain a mutable setting with no DB approval binding and `finance_manager` still holds create+post+approve), **B-05 is only schema-deep** (content not hashed, worker-deletable), and **B-06** lacks the CI parity it promised. B-02 is the one genuinely fixed auth blocker.

Minimum conditions to exit round 3: (1) register guards so a login → `me` → business-route path works end-to-end; (2) make `0001_init.sql` apply on a real Postgres in CI and align the repository columns with it; (3) unify the password hash so a seeded admin can log in; (4) enforce OTP single-use atomically, wire SMS delivery, and add step-up + scope guards; (5) move journal approval binding into the DB and make thresholds approval-governed; (6) make the audit chain content-covering and remove the worker's write access to audit rows; (7) distinct DB secrets per role and remove crown secrets from `.env`; (8) close the export owner check and the `audit.export`/cost permission mapping. Medium and Low items should be closed before the corresponding module's phase gate, but they are not what is stopping a deploy.
