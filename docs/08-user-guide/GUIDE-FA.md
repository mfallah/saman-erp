# راهنمای کاربری سامان ERP

> این راهنما برای کاربران روزمره (مدیر، حسابدار، انباردار، کارشناس فروش) نوشته شده است.
> نسخهٔ ۱٫۰ — پس از نصب و راه‌اندازی طبق `docs/06-deployment/INSTALL-FA.md`.

## ۱. ورود به سیستم

1. آدرس پنل را باز کنید (مثلاً `https://erp.carexy.shop`).
2. **موبایل** و **رمز عبور** خود را وارد کنید.
3. اگر از دستگاه جدید وارد می‌شوید، کد ۶ رقمی که با پیامک («لیمو اس‌ام‌اس») ارسال می‌شود را وارد کنید.
   - کد تا **۲ دقیقه** معتبر است؛ حداکثر **۵ تلاش**.
4. اگر کد را دریافت نکردید، «ارسال مجدد» را بزنید (محدودیت: ۵ بار در ساعت).

> نشست شما با یک توکن کوتاه‌عمر و یک توکن تازه‌سازی امن مدیریت می‌شود؛ بستن مرورگر شما را خارج نمی‌کند،
> اما «خروج» در منوی کاربر نشست را باطل می‌کند.

## ۲. داشبورد

- کارت‌های KPI: فروش امروز/ماه، سفارش‌های باز، کالاهای کم‌موجود، وضعیت هم‌گام‌سازی کانال‌ها.
- جدول سفارش‌های اخیر و کالاهای زیر نقطهٔ سفارش.
- اگر همگام‌سازی کانال یا صف پس‌زمینه خطا داشته باشد، هشدار قرمز نمایش داده می‌شود.

## ۳. کالا و تنوع کالا

| کار | مسیر | نکته |
|---|---|---|
| ساخت کالا | محصولات ← «کالای جدید» | نام، دسته، برند، واحد، توضیحات |
| افزودن تنوع (رنگ/سایز/…) | صفحهٔ کالا ← تب «تنوع‌ها» | هر تنوع SKU مستقل دارد |
| بارکد کارخانه | تب «بارکدها» | بارکد کارخانه شناسهٔ **تنوع کالا** است، نه هر واحد فیزیکی |
| ویژگی‌ها و مشخصات | تب «ویژگی‌ها» | برای فیلتر و مقایسه استفاده می‌شود |
| تصاویر | تب «رسانه» | آپلود از طریق لینک امن (S3) انجام می‌شود |
| قیمت و بهای تمام‌شده | تب «قیمت» | قیمت خرید فقط برای نقش‌های مجاز نمایش داده می‌شود |

**قاعدهٔ طلایی:** هیچ‌وقت موجودی را مستقیم «ویرایش» نکنید؛ هر تغییر موجودی از طریق
*رسید ورود*، *حوالهٔ خروج*، *تعدیل* یا *شمارش* ثبت می‌شود تا دفتر موجودی و حسابداری قابل ردیابی بماند.

## ۴. انبار

1. **ساختار مکان:** انبار ← منطقه ← راهرو ← قفسه ← طبقه ← سلول (bin) ← مکان (location).
2. **ورود کالا (Receiving):** خرید ← رسید ورود ← ثبت تعداد و بهای خرید ← سیستم مکان پیشنهادی (Putaway) می‌دهد ← اسکن بارکد مکان و کالا.
3. **برداشت (Picking):** سفارش ← «تخصیص» ← موج برداشت ← اپلیکیشن برداشت:
   - سیستم مکان دقیق را نشان می‌دهد.
   - بارکد کالا و مکان را اسکن کنید؛ تطابق نامعتبر = خطا.
   - تعداد را تأیید کنید.
4. **بسته‌بندی (Packing):** ایستگاه بسته‌بندی ← اسکن دوبارهٔ کالا ← تأیید وزن ← چاپ لیبل کانال/پست.
   (این همان «تأیید دومرحله‌ای» برای جلوگیری از ارسال اشتباه است.)
5. **شمارش دوره‌ای:** انبار ← شمارش ← ثبت شمارش ← تأیید اختلاف (سند تعدیل خودکار).

## ۵. سفارش‌ها

- **ثبت دستی:** فروش ← سفارش جدید ← مشتری/آدرس ← افزودن اقلام ← تأیید.
- **سفارش کانال:** به‌صورت خودکار از کرکسی‌شاپ/دیجی‌کالا دریافت می‌شود (در صورت فعال بودن همگام‌سازی).
- **چرخهٔ وضعیت:** پیش‌نویس → تأیید → تخصیص موجودی → برداشت → بسته‌بندی → ارسال → تحویل → بسته.
- **مرجوعی:** سفارش ← «مرجوعی» ← ثبت اقلام ← صدور سند برگشت و اعتبار مالیاتی.

## ۶. کانال‌ها (کرکسی‌شاپ، دیجی‌کالا)

- هر کانال یک «حساب کانال» با کلید API/رمز OAuth دارد؛ کلیدها رمزنگاری‌شده ذخیره می‌شوند و هرگز نمایش داده نمی‌شوند.
- **نگاشت‌ها:** کالای داخلی ↔ شناسهٔ کالا/تنوع در کانال، انبار ↔ Storage، دسته‌بندی ↔ دستهٔ کانال.
- **همگام‌سازی:** موجودی و قیمت با تأخیر کوتاه (batch) ارسال می‌شوند؛ سفارش‌ها با cursor دریافت می‌شوند.
- در صورت خطا، کار به‌صورت خودکار چند بار تلاش می‌شود و در نهایت در «صف نامه‌های مرده» قابل بررسی است.

## ۷. حسابداری

| کار | مسیر | نکته |
|---|---|---|
| اسناد روزنامه | مالی ← اسناد | بدهکار = بستانکار الزامی است؛ سند ثبت‌شده قابل ویرایش نیست |
| سند دستی | مالی ← «سند جدید» | بالای سقف تعیین‌شده نیاز به تأیید دوم دارد |
| تراز آزمایشی | مالی ← گزارش‌ها | جمع بدهکار و بستانکار باید برابر باشد |
| سود و زیان | مالی ← گزارش‌ها | بر اساس نوع حساب‌ها و مراکز هزینه |
| دفتر کل/معین | مالی ← دفاتر | قابل فیلتر بر اساس حساب و دوره |
| چک‌ها | مالی ← چک‌ها | چرخه: ثبت → در جریان → وصول/برگشتی |
| شرکا | شرکا | سرمایه، برداشت، سهم سود از سود انباشتهٔ سال بسته‌شده |

**بستن سال مالی:** فقط پس از بستن همهٔ دوره‌ها و ثبت سند بستن امکان‌پذیر است؛ سود/زیان به سود انباشته و
ذخیرهٔ قانونی (۵٪ تا سقف ۱۰٪ سرمایه) منتقل می‌شود.

## ۸. کاربران و دسترسی‌ها

- مدیر ← کاربران: ساخت کاربر، تخصیص نقش، محدودکردن شعبه/انبار.
- نقش‌ها از «مجوزها» ساخته می‌شوند (مثلاً `inventory.adjust`، `accounting.journal.post`).
- **تفکیک وظایف:** حسابدار موجودی را تغییر نمی‌دهد؛ انباردار قیمت تمام‌شده را نمی‌بیند.
- تغییر نقش/دسترسی و عملیات حساس نیاز به «تأیید مرحله‌ای» (رمز/OTP دوباره) دارد.

## ۹. گزارش‌ها و خروجی‌ها

گزارش‌ها ← انتخاب گزارش ← بازهٔ تاریخ (شمسی) ← اجرا ← دانلود (در صورت داشتن مجوز همان گزارش).
خروجی‌های سنگین در پس‌زمینه ساخته می‌شوند و پس از آماده‌شدن قابل دانلود هستند.

## ۱۰. مشکلات رایج

| نشانه | علت محتمل | کار |
|---|---|---|
| ورود ناموفق / «شماره یا رمز اشتباه» | رمز اشتباه یا قفل موقت | ۱۵ دقیقه صبر یا از مدیر «بازنشانی رمز» بخواهید |
| کد پیامک نمی‌آید | محدودیت ارسال یا قطعی سرویس پیامک | ۲ دقیقه صبر، سپس «ارسال مجدد»؛ در صورت تکرار به مدیر اطلاع دهید |
| «موجودی کافی نیست» | رزرو/رزروهای باز دیگران | موجودی و رزروها را ببینید؛ سفارش را کم کنید یا ورود کالا ثبت کنید |
| بعضی منوها نیست | نداشتن مجوز نقش | از مدیر بخواهید نقش/دامنهٔ دسترسی را اصلاح کند |
| خطای ۵۰۰ | خطای سرور | `X-Request-ID` صفحهٔ خطا را به تیم فنی بدهید |

## ۱۱. نکات امنیتی برای کاربران

- رمز عبور را با کسی به اشتراک نگذارید؛ مدیر هرگز رمز شما را نمی‌پرسد.
- روی دستگاه‌های عمومی حتماً «خروج» بزنید و دستگاه را از «دستگاه‌های مطمئن» حذف کنید.
- اسکنر/تبلت انبار را در حالت قفل نگه دارید و پس از شیفت خارج شوید.
